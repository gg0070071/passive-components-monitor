# 被动元件产业链投研监控系统

把被动元件（MLCC / 电容 / 铜箔）产业链上市公司的公开行情与财务数据，做成一套
**自动采集 → SQL 入库 → 异动归因 → LLM 生成行业月报 → 看板展示** 的可复现系统。

本项目的目的是把"数据分析"从工具名词变成可运行、可追问的交付物：
每一个数字都能回溯到一条 SQL 查询，每一步处理都能在提交历史里看到。

> 免责声明：本项目仅用于公开数据的行业观察与技术演示，不构成任何投资建议。

---

## 数据来源

全部来自公开免费接口，通过 [akshare](https://akshare.akfamily.xyz/) 获取，无需 token：

| 数据 | 接口 | 说明 |
| --- | --- | --- |
| 日线行情 | `stock_zh_a_hist` / `stock_zh_a_daily` / `stock_zh_a_hist_tx` | 前复权；**多源自动降级** |
| 财务摘要 | `stock_financial_abstract` | 按报告期，累计口径 |

行情接口做了**多源降级**（东方财富 → 新浪 → 腾讯）：单一免费接口可能限流、变更或被
网络环境拦截，脚本会依次尝试并在采集日志里记录实际使用的来源。

```

    │  sql/queries.sql              分析层（同比、异动、同业对比）
    │  src/anomaly.py               异动检测与归因（z-score）
    ▼
SQLite: fact_anomaly
    │  ai/report_input.py           把事实汇总成结构化 JSON
    │  ai/report_pipeline.py        调用 DeepSeek 生成月报
    │  ai/quality_gate.py           校验月报数字能否回溯（拦截幻觉）
    ▼
reports/月报_*.md
    │
    ▼
（规划中）Power BI 看板
```

## 快速开始

```bash
# 1. 安装依赖（SQLite 为 Python 内置，无需安装数据库）
pip install -r requirements.txt

# 2. 采集数据（约 1 分钟；已存在的文件会跳过，加 --force 强制重抓）
python src/fetch_data.py

# 3. 建库并入库（--rebuild 删库重建）
python src/load_to_db.py --rebuild

# 4. 跑分析查询
sqlite3 data/db/passive_components.db < sql/queries.sql

# 5. 异动检测与归因（写入 fact_anomaly）
python src/anomaly.py

# 6. 生成行业月报（需先设好 DeepSeek key）
export DEEPSEEK_API_KEY=你的key
python ai/report_pipeline.py            # 加 --dry-run 可离线只渲染提示词
```

> **执行顺序有依赖**：第 5 步的 `anomaly.py` 必须在第 6 步之前跑。
> `--rebuild` 会重建所有表（包括清空 `fact_anomaly`），所以如果重建过库，
> 要按 3 → 5 → 6 的顺序重跑一遍，否则月报里的异动统计会是空的。

> 注：SQLite 需要文件系统支持文件锁。若把项目放在网络盘或虚拟挂载盘上，
> 可能报 `disk I/O error`——放到本地磁盘即可。也可用环境变量 `PC_DB_PATH` 指定库的位置。

## 数据模型

**星型模型**：一张维度表 + 两张事实表。

| 表 | 粒度 | 说明 |
| --- | --- | --- |
| `dim_stock` | 每只股票一行 | 标的池：代码、简称、产业链环节、交易所 |
| `fact_quote` | 每只股票每个交易日一行 | 前复权行情：开高低收、成交量(股)、成交额(元)、换手率(%) |
| `fact_financial` | 每个"指标 × 报告期"一行 | 长表：category / metric / value |

`fact_financial` 从源数据的宽表（指标 × 报告期）转成长表，便于用 SQL 做同比与跨公司对比。

## 已知数据质量问题及处理

这几条是实际做数据时踩到、并已明确处理的坑，也是本项目最值得追问的部分：

1. **洁美科技停牌 10 个交易日**（2026-03-03 ~ 2026-03-16）。
   `fact_quote` 只存实际有交易的交易日，缺失的交易日即停牌。
   **处理**：不当作缺失值插补；用 Q2 单独识别（相对全市场交易日历找缺口）。

2. **基数为负时同比百分比没有意义**。诺德股份 2025H1 归母净利润为负，
   直接算同比会得到 -242% 这种荒谬数字。
   **处理**：Q7 在基数为负时不给百分比，改给绝对变动额。

3. **财务为报告期累计值**（如 6 月报的营收是上半年累计），因此同比必须与
   去年**同一报告期**比较（LAG 4 个季度），与相邻季度做环比会失真。

4. **各公司财务历史长短不一**（风华高科可回溯到 1993 年，洁美科技 2017 年上市），
   宽表的报告期列数从 46 到 115 不等。
   **处理**：入库时按列名动态识别报告期，缺失留空，不做插补。

5. **同一财务指标在源数据里挂在多个分组下**。源数据的 `选项` 列会把 `毛利率`、`ROE`、
   `归母净利润` 等 10 个指标同时列在"常用指标"和"盈利能力"等分组里。
   实测 5745 组重复中**数值 100% 一致**，属纯冗余而非口径冲突。
   **处理**：主键只取 `(code, report_date, metric)`，入库时按此去重（保留首次出现的分组），
   避免任何未察觉的查询重复计数。
   *（这个问题是 LLM 生成月报时自己发现的——模型在"数据说明"一节里主动指出了重复行，
   反而帮我们找到了一个真实的数据结构缺陷。）*

## 分析查询

`sql/queries.sql` 收录 9 条查询，覆盖窗口函数、CTE、多表 JOIN：

| 编号 | 内容 |
| --- | --- |
| Q1 | 标的池覆盖概览 |
| Q2 | 停牌识别（交易日历缺口） |
| Q3 | 区间涨跌幅（首末价对比） |
| Q4 | 收盘价与 20 日均线的偏离度 |
| Q5 | 异动检测（单日涨跌幅 ≥ 5%） |
| Q6 | 近 90 日波动率（手动算标准差） |
| Q7 | 财务同比（处理负基数） |
| Q8 | 同业盈利能力对比（毛利率/净利率/ROE） |
| Q9 | 产业链环节聚合 |

## AI 月报流水线（含"输出质量门禁"）

这套流水线的核心设计是**把"算数"和"写字"分开**：

1. `ai/report_input.py` — 所有数字先在数据库里查好，汇总成结构化 JSON；
2. `ai/report_pipeline.py` — 把这份 JSON 填进提示词模板，交给 DeepSeek 组织成文字；
3. `ai/quality_gate.py` — 成稿后，把月报里的**每个数字**抽出来，逐个回溯到事实数据，
   凡是在事实里找不到来源的，一律标出来。

**为什么必须有第三道门：** LLM 会非常自信地编造数字。提示词里写"只能用给定数据"并不能
可靠地阻止它——实测中把"净利润同比 500%""市占率 45%"这类凭空数字塞进月报，模型照样写得
有模有样。所以约束不能只靠提示词，必须有一道机器校验兜底。

门禁的边界要说清楚：它是**回溯校验**，只保证"月报里的数字有出处"，不保证"数字的业务含义
正确"。后者仍需人工判断。

**一次真实的调优（值得面试讲）：** 第一版月报跑出来，门禁拦下 3 个数字——
`232`、`238`、`91.8`。查下去发现它们不是幻觉，而是模型**自己算的**：
两个环节内部收益的差值，以及 56÷61 的占比。算术都对，但门禁只认"事实数据里有的数字"，
所以一律拦截。

这暴露了设计缺陷，修法是两条：
1. **把有用的派生指标提前在管道里算好**（`derived.segment_spread`、`derived.anomaly_share_pct`），
   让模型直接引用而不是自己算；
2. **提示词里明确禁止任何计算**（差值、比例、倍数、占比都不许），并说明原因——
   你算的数过不了门禁。

核心原则一句话：**管道负责算，模型负责写。** 只要这条守住，门禁就能既严格又不误伤。

```
python ai/report_input.py --out /tmp/facts.json     # 导出事实
python ai/quality_gate.py reports/月报_xxx.md /tmp/facts.json
```
